# legends readme presentation

The Legends house default is one visible product title: the branded banner.
Use the exact lowercase, hyphen-separated repository name in the banner and
its image alt text. Make the image the first-level heading so GitHub supplies
the heading separator. Preserve an explicit named anchor for existing links.
Do not repeat the product name as a second visible text heading.

Immediately below it, use three linked badges in this order:

| badge | source | click destination |
|---|---|---|
| release | latest published stable GitHub release, sorted by date | latest release |
| checks | designated CI workflow on the default branch | that workflow |
| license | repository license metadata | LICENSE |

Use `flat-square`, black labels, red for the release value, and gray for the
license value. Let the checks badge report its real status and status color.
Do not hard-code passing status. Versions and license identifiers retain
their actual spelling; editorial badge labels are lowercase.

Badges are compact information and navigation, not compatibility certificates.
Do not put vendor-logo rows, stars, last-commit dates, language inventories,
or duplicate brand labels in this header. Explain platform requirements,
agent setup, tested compatibility and limitations in the README body.
Never remove those requirements merely because a badge is removed.

After the badges, preserve the authored product explanation and provide a
clear installation or start path. Keep one canonical instruction package
where applicable, with client-specific loading instructions as needed.
Only claim agent workflows supported by actual integration and verification
evidence. A portable instruction file alone does not certify every client.

This is the Legends presentation default, not a mandatory template for every
repository audited by this toolkit. Preserve a third-party owner's design.
Repositories without a banner should retain a normal text heading.

The current rollout covers legends-geogrid, legends-stable-audio-3,
legends-obs-kit, legends-github, hyperyap and legends-dataforseo-kit. legends-seo-dungeon is explicitly
excluded for now. Header edits do not update historical release archives.

The wolf mascot and wolf-based illustrations are retired. Do not use them in READMEs, installer artwork, banners, or social previews. Use the approved typography banner.

Social cards follow [the fixed-layout, agent-first upload SOP](social-preview-sop.md).
